# Drake remote-execution runner image

This image extends a pinned official Ubuntu 24.04 base with Drake's complete,
commit-matched developer prerequisites for Buildbarn remote execution,
including:

- Ubuntu 24.04 LTS (Noble), x86-64
- CMake
- GCC 13 through Noble's `build-essential`
- GNU Fortran 13
- Clang 20 and its runtime from Ubuntu's Noble packages
- Noble's default LLD, as selected by Drake's prerequisite installer
- Python 3.12 development headers

The Docker build downloads the pinned Drake source archive only to run
`setup/install_prereqs --developer -y`, which is the authoritative list of
supported Noble packages. The archive is removed in the same image layer and
is not retained in the final image.

The image also installs a narrow compatibility wrapper at Clang's resolved
`/usr/lib/llvm-20/bin/clang` path. It rewrites the invalid
`-fuse-ld=/usr/bin/ld.lld` option generated by `rules_cc` local toolchain
autoconfiguration to `-fuse-ld=lld`; all other arguments are passed unchanged
to Ubuntu's packaged Clang 20 binary. The wrapper handles the option both as a
direct argument and inside Bazel `@response` files, copying affected response
files to temporary rewritten files instead of modifying Bazel's inputs.

Drake source is not included. Bazel runs on the client, while source files and
declared build inputs reach workers through the remote-execution
content-addressable store.

## Build and publish

From the `hermetiq-helm-gke` checkout, build the required Linux x86-64 image
and publish it to a registry reachable by the cluster. Authenticate Docker to
that registry first, then use a unique version tag for each change:

```bash
IMAGE=<registry>/drake-runner:ubuntu24-clang20-v1

docker buildx build \
  --platform linux/amd64 \
  --file examples/drake-runner-image/Dockerfile \
  --tag "$IMAGE" \
  --push \
  examples/drake-runner-image
```

Resolve the published image to its immutable digest:

```bash
docker buildx imagetools inspect "$IMAGE"
```

Record the `linux/amd64` digest as:

```text
<registry>/drake-runner@sha256:<digest>
```

Do not deploy the mutable version tag.

## Verify

Run the published x86-64 image and check the supported environment directly:

```bash
docker run --rm --platform linux/amd64 "$IMAGE" sh -lc \
  'cat /etc/os-release; uname -m; test -f /usr/include/x86_64-linux-gnu/python3.12/pyconfig.h; python3 -c "import yaml; print(yaml.__version__)"; cmake --version; gcc --version; gfortran --version; clang-20 --version; ld.lld --version'
```

Consumers should use the immutable `<registry>/drake-runner@sha256:<digest>`
reference reported above. If another missing system dependency appears during
a Drake build, add only the package justified by that failure and publish a new
version.
